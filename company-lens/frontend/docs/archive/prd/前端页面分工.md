## 三、飞飞负责的模块

### 3.1 首页与产品入口

负责目录：

- `src/pages/home`
- 首页使用的产品介绍区块和首页级样式

负责内容：

- `/` 首页的产品定位、核心价值、使用流程和主要 CTA。
- 从首页进入 `/research/new` 的导航，以及登录、历史分析等入口的展示。
- 首页的响应式布局、可访问性、空状态和基础交互。
- 首页曝光、研究入口点击等已确认埋点的接入。

边界：

- 首页只负责产品入口和导航，不在首页内复制研究输入、对象识别或任务创建逻辑。
- 研究表单和识别状态由 gxq 负责的“研究发起与对象识别”模块承载。
- 首页不因为用户未登录而阻断研究入口。

### 3.2 认证与账号

负责目录：

- `src/pages/login`
- `src/features/auth`

负责内容：

- 登录 / 注册页面及表单切换、输入校验、提交中、成功、失败和重试状态。
- `GoogleLoginButton` 及第三方登录回调处理。
- token、用户信息、会话恢复、退出登录和未授权状态处理。
- 登录成功后的默认跳转和 `returnTo` 路径恢复。
- 与认证接口联调，以及认证错误到用户可见状态的转换。

产品边界：

- 开始研究不要求登录；游客可以完成对象识别、研究、进度查看和报告查看。
- 登录主要服务于历史分析、匿名报告保存到账户和账户管理，不在登录页内实现研究任务逻辑。

协作边界：

- gxq 只通过 `useAuthStore`、`getAuthToken` 或约定的身份接口消费登录态，不自行解析 token 或复制用户状态。
- 认证状态、用户 ID、登录跳转协议发生变化时，飞飞需要同步 gxq 和受影响的研究页面。

### 3.3 历史分析与报告保存

负责目录：

- `src/pages/history`
- `src/features/research-history`
- `src/features/save-report-to-history`

负责内容：

- `/history` 历史分析列表、记录状态、对象信息、时间和摘要展示。
- 登录用户的搜索、分页 / 加载更多、进入记录和删除确认流程。
- 未登录用户的 deviceId 历史预览、登录提示和预览条数限制。
- 根据记录状态进入研究进度页或统一结果页，并使用稳定的 `taskId` 定位记录。
- 报告页中的“保存到历史”能力，包括登录入口、绑定任务、成功、失败和重试状态。
- 历史分析相关的页面曝光、搜索、进入、删除、保存和登录转化埋点。

边界：

- 历史记录页不重复实现研究进度和报告内容，只展示记录摘要并跳转到对应页面。
- 历史模块不自行判断研究任务是否完成，状态映射以统一的研究领域模型和接口契约为准。
- `src/features/save-report-to-history` 当前作为独立能力存在；最终接入结果页时，飞飞负责保存交互和账户侧行为，gxq 负责提供入口位置、`taskId` 和研究状态边界。

### 3.4 应用壳层与公共体验

负责目录：

- `src/widgets/app-header`
- `src/widgets/app-shell`
- `src/shared/theme`
- `src/shared/i18n`
- `src/shared/ui`
- `src/shared/analytics`

负责内容：

- `AppHeader`、`AppShell`、全局导航、移动端返回入口和跨页面布局约定。
- light / dark theme、语言切换、默认 locale 和用户偏好持久化。
- `Button`、`PageState`、`MarkdownContent`、`BackToTop` 等公共 UI 的维护和 API 稳定性。
- 公共 loading、empty、error、disabled、focus 和响应式状态的视觉语义。
- 埋点基础接线、事件命名和公共属性约定；页面负责人提供准确的业务触发时机。

边界：

- 公共组件只提供稳定的展示和交互能力，不直接读取公司研究业务对象。
- gxq 可以提出研究报告、进度或分享模块的公共能力需求，但新增 API 前先确认至少两个使用场景和数据边界。
- 公共组件 API、token、主题或 i18n 发生破坏性变化时，双方共同确认并检查所有消费者。

## 四、gxq 负责的模块

### 4.1 研究发起与对象识别

负责目录：

- `src/pages/research`
- `src/features/research-launch`

负责内容：

- `/research/new` 页面编排和研究对象输入体验。
- 输入长度、去空格、示例切换、输入错误、提交中和重复提交防护。
- 通过 `recognition SSE` 识别公司、股票、人物、产品、品牌、子公司或业务板块。
- 明确识别结果的自动进入任务流程。
- 多候选结果的弹窗、候选项可研究状态、不可研究原因和用户选择。
- 识别失败、断流、无法识别、创建任务失败和返回首页等恢复路径。
- 识别与创建任务时的 `language`、`conversationId`、`recognitionId`、`candidateId` 和稳定 `taskId` 传递。

边界：

- 研究发起不要求登录；匿名身份由公共 request client 和 deviceId 能力统一处理。
- 只负责启动任务并进入进度页，不在启动表单中展示完整研究报告。
- 候选对象和任务创建的接口 DTO 由 `entities/company-research` 负责解析，页面只消费领域类型。

### 4.2 公司研究领域模型与接口

负责目录：

- `src/entities/company-research`
- `src/entities/market`

负责内容：

- `CompanyResearchRecognition`、`CompanyResearchTask`、`CompanyResearchCapability`、`CompanyResearchReportDocument` 等领域类型。
- recognition SSE、任务查询、任务事件、报告、能力结果、重试和任务绑定等 Repository 能力。
- API DTO 的字段兼容、长 ID 转 string、snake_case / camelCase 兼容和未知状态兜底。
- `pending`、`running`、`synthesizing`、`succeeded`、`partial`、`failed` 等任务及能力状态的归一化。
- `reportReady` 与任务终态的组合判断，避免把 `progress=100` 误当成报告已经可读。
- React Query key、缓存更新、任务事件触发后的快照刷新和错误归一化。
- 报告字段、研究能力摘要、来源、结论和附加区块的领域层 helper。

边界：

- API 层只负责请求、解析、归一化和缓存，不直接渲染页面。
- 进度页、结果页、Agent 报告页和公司详情页不得各自解析一套后端 DTO。
- 接口契约变化先在该模块完成领域模型和测试，再通知飞飞检查历史、保存和公共状态消费者。

### 4.3 研究进度

负责目录和路由：

- `src/pages/research-progress`
- `/research/:projectId/progress`

负责内容：

- 研究对象识别结果、公司信息、市场和研究任务元数据展示。
- Agent / capability 的排队中、运行中、报告生成中、成功、部分完成、失败和取消状态。
- Agent 进度、阶段信息、可见思考事件、摘要、来源和错误原因展示。
- 研究整体进度、任务快照刷新、SSE / 事件订阅生命周期和页面离开后的清理。
- 已完成能力进入 Agent 报告、任务完成后进入统一结果页，以及失败后的重试 / 返回路径。
- 直接访问、刷新、任务不存在、加载失败和请求重试状态。

边界：

- 页面只消费 `CompanyResearchTask` 等统一领域模型，不直接解析 SSE 或自行累加 Agent 状态。
- `RUNNING + progress=100` 仍可能处于报告生成阶段；只有服务端确认 `reportReady` 且任务状态允许时才提供报告入口。
- 页面离开只停止当前页面的订阅，不代表取消服务端任务；取消能力需要单独的产品和接口确认。
- 不在进度页复制统一结果页、Agent 报告详情页或公司详情页的展示模板。

### 4.4 统一研究结果

负责目录和路由：

- `src/pages/research-result`
- `/research/:projectId/result`

负责内容：

- 研究对象、公司基础信息、综合结论和对输入对象的直接判断。
- 商业模式、护城河、财务质量、行业竞争、管理层、风险、估值、研究共识和核心分歧等报告模块。
- 结构化 `report` 与 `reportMarkdown` 的展示优先级、旧数据兼容和缺失字段兜底。
- Agent 报告入口、公司详情入口、来源信息、目录定位和返回研究进度入口。
- 完整结果、部分结果、报告生成中、报告缺失、加载失败和重试状态。
- 结果页到 `SharePayload` 的 mapper，以及与“保存到历史”能力的接入。

边界：

- 结果页负责报告信息架构和业务展示，不直接处理截图、复制、上传或平台分享 API。
- 结果是否可分享以统一领域状态和分享能力返回为准，不在页面内重复推断服务端状态。
- 结果页只消费稳定的 `taskId`、`agentId`、`companyId` 和领域数据，不依赖历史列表的内存对象。

### 4.5 Agent 报告详情与公司详情

负责目录和路由：

- `src/pages/agent-report`
- `src/pages/company-detail`
- `/research/:projectId/agents/:agentId/report`
- `/research/:projectId/companies/:companyId`

负责内容：

- Agent 报告详情页的统一模板、研究范围、报告正文、来源 / 证据、结论、风险和缺失状态。
- 不同 Agent 的字段差异通过领域 mapper、配置或报告 block 适配，不复制页面入口。
- 公司详情页的公司基础信息、入选原因、关键指标、研究结论、风险、来源和上下文返回。
- 不同 Agent、不同公司的加载、部分数据、缺失字段、失败和重试状态。
- 公司详情页的公司维度 `SharePayload` mapper，并接入统一分享能力。

边界：

- Agent 报告页和公司详情页都复用统一页面模板，不为每个 Agent 或公司创建独立页面。
- 页面不把后端 DTO 直接扩散到展示组件，字段适配在 page model 或 entity helper 边界完成。
- 页面不自行实现账户、历史记录、复制、截图和上传逻辑。

### 4.6 分享能力

负责目录：

- `src/features/share`
- `src/pages/research-result/model/research-result-share.mapper.ts`
- `src/pages/company-detail/model/company-share.mapper.ts`

负责内容：

- 研究结果和单家公司两类分享 payload 的构建约定。
- `ShareDialog`、分享预览、复制文字、分享链接、生成海报、下载图片和系统分享。
- X、Reddit、Telegram 等平台动作，以及能力检测和平台不可用时的降级。
- 海报截图、图片上传、资源 pending / ready / error、失败和重试。
- 分享过程的状态反馈、重复点击防护和分享相关错误归一化。

边界：

- 业务页面只负责将领域对象转换为 `SharePayload`，不直接调用 Clipboard、Web Share、截图或上传 API。
- 分享模块不反向读取 `CompanyResearchTask`、Agent 或 Company 原始对象，避免与研究页面形成反向依赖。
- 分享能力的通用 UI 和适配器由 gxq 维护；公共 Dialog / Button / theme 变化与飞飞同步。
