# C 端交互视觉规则 PRD

> 状态：待产品、设计与用户验收。  
> 来源：2026-07-20 用户提出的 C 端样式规则，并参考 WCAG 2.2、WAI-ARIA Authoring Practices、Apple Human Interface Guidelines 与 Material Design 的通用交互原则。  
> 适用范围：运行在浏览器内的金融类 C 端 Web 与 H5；不覆盖原生 App。业务专项规则可在此基础上追加，不得降低本规则的可用性与可访问性底线。

## 1. 目标

- 用户无需尝试即可区分“可以操作”“当前选中”“只读重点”“状态提示”。
- 所有操作在鼠标、键盘和触控场景下都有及时、稳定且一致的反馈。
- 浅色与深色主题保持相同的交互层级和状态含义。
- 金融信息保持可信、克制和清晰，不用装饰性胶囊、强阴影或高饱和色制造虚假操作感。

## 2. 目标用户与场景

目标用户为使用账户、资产、行情、投顾、风控、支付或财富管理能力的个人用户。核心场景包括：浏览资产信息、切换范围或筛选条件、提交操作、查看结果与理解风险状态。

用户可能在单手触控、弱网、强光、夜间、键盘操作、放大字体或辅助技术环境中使用产品，因此交互不能依赖单一输入方式或单一颜色线索。

## 3. 交互对象定义

| 类型               | 用户预期                               | 必须具备的视觉与行为                                            |
| ------------------ | -------------------------------------- | --------------------------------------------------------------- |
| 主按钮             | 提交当前页面最重要的任务               | 每个页面或任务区原则上只有一个主操作；具备完整状态反馈          |
| 次按钮             | 执行次要、可替代或低频操作             | 视觉权重低于主按钮；状态反馈完整                                |
| 危险按钮           | 执行删除、终止、清空等高风险操作       | 与普通操作在颜色和位置上分离；执行前提供必要确认                |
| 文本链接           | 跳转到其他页面、层级或资源             | 文案说明目的；可识别为导航，不伪装成普通正文                    |
| 选项或 Tab         | 在同一层级切换范围、模式或内容         | 明确表达当前选中项；切换后内容和状态同步更新                    |
| 可点击卡片或列表项 | 点击整个区域进入详情或执行单一动作     | 整个区域都可操作，并具备与按钮等价的反馈和可访问名称            |
| 只读重点           | 强调金额、结论、风险或业务结果         | 通过颜色、字重、标记和文案表达；无指针、hover、focus 或按压反馈 |
| 状态提示           | 表达成功、稳定、观察、风险、失败等状态 | 使用“颜色 + 标记或图标 + 文案”，不得仅用颜色或按钮形胶囊        |

## 4. 可点击与不可点击的视觉边界

### 4.1 可点击对象

- 所有按钮必须提供 `default / hover / pressed / focus / disabled` 状态；异步操作还必须提供 `loading / success / error` 反馈。
- 点击或触控后应在 100ms 内出现按压反馈，状态过渡建议在 150–300ms 内完成。
- 支持鼠标 hover 的设备显示 hover；触控设备不依赖 hover 传递必要信息。
- 可点击对象使用稳定的边界、底色、文字样式或导航样式，不在 hover/pressed 时改变占位尺寸。
- 图标操作必须配有可访问名称；不熟悉的图标还需提供可发现的名称说明。

### 4.2 不可点击对象

- 不使用按钮边框、按钮底色、分段控件、带投影胶囊或手型指针。
- 不提供 hover、pressed、focus 或点击后反馈。
- 静态卡片和静态表格行不因鼠标经过改变底色或浮起；需要辅助扫读时，使用固定分隔、斑马纹或排版层级。
- 数量、标签和状态若位于可点击容器中，仍不得看起来像容器内的第二个独立按钮。

### 4.3 状态与重点

- 正常、成功：绿色 + 圆点或勾选标记 + 明确文案。
- 关注、等待、中风险：琥珀色 + 圆点或提示标记 + 明确文案。
- 失败、高风险、阻断：红色 + 错误或阻断标记 + 原因及下一步。
- 中性、稳定、已归档：中性色 + 中性标记 + 明确文案。
- 金融涨跌必须同时保留方向箭头、正负号或涨跌文案；颜色约定可按市场切换，但含义不得只依靠红绿。

## 5. 状态矩阵

| 状态       | 视觉要求                                          | 行为要求                                       |
| ---------- | ------------------------------------------------- | ---------------------------------------------- |
| `default`  | 清楚表现操作层级和可点击性                        | 可被鼠标、键盘或触控触发                       |
| `hover`    | 背景、边框或文字产生轻微变化，不能发生布局位移    | 仅在支持 hover 的设备出现；移出后恢复          |
| `pressed`  | 比 hover 更明确，可使用更深状态层或轻微透明度变化 | 指针或手指按下后立即反馈，释放后执行动作       |
| `focus`    | 使用持续可见且对比度足够的焦点指示                | 键盘顺序与视觉阅读顺序一致，焦点不能无故丢失   |
| `disabled` | 降低强调但保持可读，且与普通状态明显不同          | 不响应操作；在用户可能疑惑时说明不可用原因     |
| `loading`  | 保持原尺寸，显示进度与进行中文案                  | 阻止重复提交；完成后进入成功或错误状态         |
| `success`  | 明确告知任务已完成                                | 必要时提供下一步或撤销入口                     |
| `error`    | 说明发生了什么以及如何恢复                        | 保留用户输入或上下文，提供重试、修改或求助路径 |

状态优先级从高到低为：`disabled → loading → pressed → focus → hover → default`。高优先级状态出现时，不叠加会造成误解的低优先级表现。

## 6. 选中态与高亮态

### 6.1 选中态

选中态表示用户已经做出的选择或当前所在位置，至少同时使用以下三类信号中的两类：

- 选中底色或文字色；
- 边框、指示线、勾选标记或当前位置标记；
- 字重变化和可被辅助技术识别的“已选中/当前项”状态。

切换主题、周期、筛选或导航时，选中态必须立即同步，且同组只能存在符合业务规则的选中数量。

### 6.2 高亮态

高亮态只表达业务重点，不代表可以操作。金额、风险、结论和状态优先使用语义颜色、字重、标记和说明文案，不使用按钮轮廓、hover 或手型指针。

### 6.3 只读与禁用

- 只读内容仍可阅读、选择和复制，只限制编辑；不应使用 disabled 的低透明度样式。
- disabled 是原本可以操作但当前不可用的控件；不可把普通静态内容标记为 disabled。
- 当操作因资格、余额、时段、网络或前置条件不可用时，用户应能获知原因。

## 7. C 端触控与响应式

- 所有交互目标的可触控区域不小于 `44 × 44px`，相邻目标之间至少保留 `8px` 安全间距。
- 图标视觉尺寸可以小于 44px，但实际可触控区域不能缩小。
- H5 以单手操作为前提，主要操作避免贴近屏幕边缘、系统手势区或被固定栏遮挡。
- H5 顶级导航优先使用不超过 5 项的底部导航，Web 使用稳定的顶部主导航；两端的名称、顺序、当前位置和信息层级保持一致。
- H5 底部导航必须预留浏览器与设备安全区，页面滚动内容不得被固定导航遮挡。
- 不使用只能精确点中细线、小圆点或文字局部的交互。
- 在 `320px` 起的窄屏、横屏和放大字体环境中，按钮文案允许换行但不得溢出或遮挡相邻内容。

## 8. 可访问性与动效

- 正文与背景对比度不低于 `4.5:1`；大字、边界、图标和焦点指示不低于 `3:1`。
- 颜色不是唯一信息来源；状态变化需由文案、标记、图标或结构共同表达。
- 用户仅使用键盘也能完成主要任务，弹层打开与关闭后的焦点位置符合任务路径。
- 重要状态变化对辅助技术可感知，但不会无故抢占焦点。
- 用户启用 reduced motion 时，取消非必要位移和缩放；状态仍需通过颜色、边界或文字清楚表达。
- 浅色与深色主题分别校验对比度、hover、pressed、focus、disabled、selected 和状态色，不以单一主题结果推断另一主题。

## 9. 验收标准

| 编号  | 验收场景                       | 通过条件                                                            |
| ----- | ------------------------------ | ------------------------------------------------------------------- |
| AC-01 | 鼠标依次经过所有按钮和链接     | 每个可点击对象都有一致、可见且不位移的 hover；静态内容无 hover 暗示 |
| AC-02 | 按下按钮或选项                 | 100ms 内出现 pressed 反馈，释放后执行且不会重复触发                 |
| AC-03 | 仅用键盘完成主要路径           | 焦点始终可见，顺序合理，所有操作可触达且可退出                      |
| AC-04 | 查看 disabled 与 loading       | 两者视觉和行为不同；均不可重复操作，loading 不引发布局跳动          |
| AC-05 | 查看正常、稳定、观察和风险状态 | 均以颜色 + 标记 + 文案表达，且不呈现为可点击按钮或独立胶囊          |
| AC-06 | 切换导航、主题、周期或筛选     | 当前项至少有两种视觉信号，并能被辅助技术识别为当前或已选中          |
| AC-07 | 在 375px 触控设备操作          | 所有目标不小于 44px，相邻操作间距合理，无误触和横向溢出             |
| AC-08 | 分别检查浅色与深色主题         | 交互层级、语义颜色和全部状态均清楚，文字与 UI 对比度达标            |
| AC-09 | 开启 reduced motion 与放大字体 | 主要路径可完成，无关键内容遮挡、溢出或依赖动效才能理解的状态        |
| AC-10 | 使用屏幕阅读器检查状态变化     | 控件名称、当前/选中/展开/禁用状态和重要结果可被正确理解             |
