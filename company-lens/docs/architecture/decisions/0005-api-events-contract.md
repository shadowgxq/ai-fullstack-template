# ADR-0005：公开DTO与快照加持久事件

> 日期：2026-09-16｜状态：proposed（沿用Run API方向并补快照高水位）  
> 实施/验证证据：尚无。

## 背景

现有UI需要替换旧接口；直接透传LangGraph事件或模型token会让前端绑定内部版本，断线也难判定真实状态。

## 决定

FastAPI输出专用公开DTO；公共schema导出OpenAPI并生成前端类型。关键应用事件持久化，按run事务性序号续读；快照包含一致高水位，SSE只通知状态。

## 后果

需要ReadModel与schema检查；投影可能短暂滞后但可解释。客户端需处理重复、过期游标与状态校准；不能把流结束当业务完成。

## 未采用的替代方案

前端手写两套DTO；直接返回Saver对象；内存序号从0重置；用固定timer生成进度。

## 复议触发条件

只读页面最初可用轮询验证，但R2要求的重连和真实进度行为必须完成。性能明确需要时才优化事件分发，不改变持久事实源。
