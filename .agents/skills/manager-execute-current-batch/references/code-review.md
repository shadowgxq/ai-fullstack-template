# 独立代码审查

默认派一个实际可用的原生通用 subagent 承担只读 Reviewer 职责；用户明确 review=off 时省略。Reviewer 不参与实现或状态回写，也不审查自己实现的改动；当前会话负责协调与进度。

1. 逐 Change 交接需求、目标文件及实际 diff、相关契约与项目规范、已有检查结果。明确本次审查的内容版本，可直接引用现有 diff 或 commit；无需新增凭证或记录格式。
2. 审查期间保持目标 diff 及其依赖契约稳定；其他读写互不冲突的任务可并行继续。Reviewer 检查逻辑、权限、契约、token/组件和源码可判断的 UI 问题，不启动浏览器，不重复运行没有疑点的检查。
3. 输出具体问题、文件位置、影响和修复建议。无法从代码证明的视觉/交互疑问列为人工待验；仅风格偏好不阻塞。实现者修复、复验后，由 Reviewer 定向复查；后续改动使结论失效时，同样只复查受影响范围。
4. 必要检查与独立审查通过后，协调者标记该 Change code-verified 并释放下游依赖；发现问题时先修复并完成定向复查，收到审查报告本身不代表通过。阶段收尾只补集成及新增 diff，可复用同一 Reviewer 与仍有效的结论。

没有实际独立线程时报告审查未完成；当前会话可继续实现、自查及其他无依赖工作，所需审查未完成的 Change 保持未通过，不将自查登记为独立审查。
