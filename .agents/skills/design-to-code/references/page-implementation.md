# 页面实现与准确性

先建立当前任务的区块/状态检查范围，再实现，不拿图层数量当组件数量。读取完整页面用于理解宿主不扩大写入授权；局部任务只改受影响区域并核对必要集成。保持现有数据、权限、事件、路由和用户任务；Mock 只用于独立授权测试夹具，不进入业务实现。

先还原容器宽度、区块顺序、布局关系、留白和层级，再细化字体、间距、颜色、圆角与图标。默认使用目标平台的流式/约束布局，避免把画布坐标逐项翻译为绝对定位。确需叠层或固定元素时注明依据。

复用核实的组件 API 和样式方式；选择、归属和抽取服从项目治理，没有政策时才按稳定语义/状态/重复/共享需要就近实现。不为未来可能的复用设计通用库，不引入新的 UI/样式依赖，不因单页稿修改共享缺省或正式设计源。

按项目 Token 政策使用相关语义，控件尺寸/状态通过已有契约；复核主题、别名、业务/操作语义和必要例外，不新增平行数值表。系统/宿主 UI 与应用壳、页面各有承担者，不能一律重绘或删除顶栏。

只实现请求的断点、主题及状态，保存状态动作/条件。设计只有一张桌面图时不能声称移动端也是精确还原；可依项目响应式规范合理适配并标注推断。

MCP 返回代码仅解释结构和样式；不要复制带框架假设、外部脚本或临时访问 URL 的代码。使用的缓存资产进入目标项目正式资产目录，生产 import/URL 不得指向 `.design-cache/` 等本地证据缓存。

实施后审查真实 API、公开边界、状态拥有者、复用与 Token 语义，并运行已授权的必要检查；Lint 成功不代替这项审查。记录采用 [共同交接字段](../../DESIGN-WORKFLOW.md#最小交接)，保留当前任务覆盖的区块/状态和实际检查证据，不重复生成中间文档。
