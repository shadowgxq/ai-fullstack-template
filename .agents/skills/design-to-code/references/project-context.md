# 实现所需的项目映射

通用发现与规则读取见 [共同协议](../../DESIGN-WORKFLOW.md#共同读取协议)。本页只维护设计到实现的 API/Token/消费者核对；文档用于规则与定位，涉及映射/导入时必须定向读相关真实源码，即使清单已有说明也不省略。

信息足够即可继续。只读项目调查仅返回页面位置、组件/变体/API、Token 来源、资产约定、检查及运行命令、缺口；用户要求时才更新现有文档，不改源码或设计缓存。

核对目标包的实际平台/版本/样式、目标页面及直接依赖，避免根依赖推断平台。对候选组件检查 public/internal/pattern、真实 export/类型、尺寸/变体/状态能力与必要调用点；按项目选择顺序确定复用/组合/新增和状态拥有者。不为清单过期新增代码出口，不为完成设计名称一一对应新增壳层。

每个关键映射记录：设计角色/节点 → 真实组件/变体/API → 语义 Token → 有效值/平台。设计变量保存名称、别名、主题模式及解析值；无变量时引用直接样式及节点，不伪造变量。未知不等于 0。

对交互控件补充真实 props、值与事件、状态拥有者和用户动作 → 可观察结果；例如设计中的 loading/disabled 变体应核对目标组件实际能力，不能只因外观相同就写入不存在的 React prop。公共库身份、实例覆盖和消费稿版本一起引用，不将变体命名或 metadata 当作运行逻辑。有效值是本次解析证据，生产代码继续引用正式 Token/组件契约，不另存一份长期数值表。

只读任务相关的 Token 选择范围及正式源；控件内部参数通过真实组件 API 使用。项目语义不可读时记录具体缺口，不能以全量导出或同值别名替代用途判断。状态及宿主/应用壳适配沿用同一项目规则与当前任务记录。

同色不等于同语义 Token；同名设计组件不等于同 API。共享 Button 不能为了一个页面改全站高度。页面已经授权重排时不能以复用为由保留旧布局。明确记录规范适配，不对偏离原图的结果声称像素一致。

仅对任务实际依赖的 Token、组件 API、相关设计库/资产、配置及代码构建记录 hash/标识。它们变化使目标映射和验证失效，不使不变的源设计自动重拉。不要 hash 整个 node_modules 或全仓库。
