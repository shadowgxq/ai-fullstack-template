## AC-001 — 未登录入口与隐私

需求来源：PRD §3.5、§4；设计交付「未登录欢迎页」。

前置条件：无登录态，直接访问带 group/q 的收藏深链。

操作：查看桌面和手机欢迎页，打开并关闭主登录弹窗，再登录测试账号。

预期：欢迎页解释用途和私有范围，示例明确为静态、没有伪操作；未登录不请求/展示私有收藏；关闭弹窗和完成登录均保留有效深链。

## AC-002 — 账号会话与重访持久化

需求来源：PRD §3.1、§3.5、§6；既有认证契约。

前置条件：独立的本轮 A/B 测试账号。

操作：注册、密码登录、保存资料、刷新、退出并再次登录。

预期：登录身份由真实 API 核实；退出后不显示私有内容，撤销 token 不能访问；重访能找到原收藏与分组。

## AC-003 — 保存、默认归组与重复链接

需求来源：PRD §3.1。

前置条件：A 账号可用，无当前用例数据。

操作：仅填有效标题和链接保存；再次用相同 URL、不同标题保存；第三条明确选择分组及备注。

预期：最小输入可保存，省略分组归未分组；允许重复 URL；每条只属一个分组且内容完整，数量与成功反馈正确。

## AC-004 — 收藏字段边界与错误保留

需求来源：PRD §3.1；OpenSpec bookmark-core / Private bookmark lifecycle。

前置条件：新建或编辑表单打开，使用合成中文及 emoji 数据。

操作：检查标题 trim 后 1/80/81 字符、URL 空值/HTTP/HTTPS/非法协议和 2048/2049 长度、备注 0/500/501 字符；提交后纠错。

预期：按 Unicode 字符校验标题和备注；合法边界可保存，越界或非法输入定位到字段并保留其他输入；不要求真实访问链接，失效 URL 不导致既有收藏自动消失。

## AC-005 — 编辑回填、取消及更新

需求来源：PRD §3.1、§3.2。

前置条件：已有含分组和多行备注的收藏。

操作：打开编辑，改动后取消并刷新；再次编辑标题、URL、分组、备注并保存。

预期：完整回填；取消不修改持久数据；保存后四项更新并可重访，只有成功内容更新排序与最近时间。

## AC-006 — 删除收藏确认

需求来源：PRD §3.1、§6。

前置条件：分组中存在目标收藏及另一条保留收藏。

操作：打开删除提示，先取消，再重新打开并确认。

预期：明确目标标题/链接和不可恢复后果；取消无写入；确认只删除目标，所属分组与其他资料保留，数量和有效页正确。

## AC-007 — 备注和安全外链

需求来源：PRD §3.1、§3.2；技术方案安全外链约束。

前置条件：一条有多行备注、一条无备注；URL 指向批准的 loopback 页面。

操作：查看两种备注；通过真实外链动作打开新标签，再回到收藏夹。

预期：只读备注完整或显示暂无备注；新标签访问保存的原 URL，原标签的 group/q/page 与浏览位置保留；使用 noopener 安全边界。

## AC-008 — 更新时间与稳定排序

需求来源：PRD §3.2–3.4；技术方案排序规则。

前置条件：记录合成资料的服务端 ID、updated_at 和顺序。

操作：新增、编辑、实际移动、同目标移动、重命名分组；读取刷新结果；补充相同时间排序样本。

预期：按 updated_at 新到旧、同时间 ID 稳定排序；实际内容或归组变化更新时间；同目标移动和分组改名不改变原时间/顺序；最终以真实 PostgreSQL 回归证明同时间与事务语义。

## AC-009 — 分页及失效页回退

需求来源：PRD §3.2、§6。

前置条件：当前条件恰有 11 条合成收藏。

操作：翻到第二页，删除或移走该页唯一一条；另检查空集合。

预期：每页 10 条，展示当前条件总数；越界后回最后有效页，仍有数据不落空页；真正无数据显示相应空态。

## AC-010 — 标题/URL 字面搜索

需求来源：PRD §3.2；OpenSpec bookmark-core / Consistent find and pagination。

前置条件：标题、URL、仅备注分别包含不同关键词，另含 %/_/反斜线样本。

操作：提交有首尾空格和大小写变化的关键词，分别匹配标题、URL及仅备注词。

预期：仅标题或链接的字面子串匹配，英文大小写不敏感且 trim；不把备注纳入搜索，也不把 %/_ 当通配符。

## AC-011 — 联合筛选、计数和 URL 恢复

需求来源：PRD §3.2；技术方案 URL 状态。

前置条件：两个分组各至少 11 条且关键词跨组分布。

操作：在第二页改变关键词/分组、清空关键词、选择全部、刷新及前进后退。

预期：group 与 q 同时生效；筛选变化从第一页开始；分组旁数量不随搜索改变，结果总数随条件变化；有效深链与历史恢复语义保持一致。

## AC-012 — 分组创建和名称规则

需求来源：PRD §3.3；OpenSpec bookmark-groups / Private one-level groups。

前置条件：A/B 独立账号，A 已有一个名称样本。

操作：创建空组；测试 trim 后 1/30/31 字符、空白、大小写重名、全部/未分组；B 创建与 A 相同名称。

预期：一级空组可创建；A 的非法/重名/系统名称被拒且有说明；同名规则仅限同一账号；固定入口不能维护。

## AC-013 — 重命名不改资料归属

需求来源：PRD §3.3。

前置条件：组内至少两条收藏，已记录 ID、时间与顺序。

操作：改有效新名称，检查表单选项、侧栏/手机选择器和收藏显示。

预期：各处使用新名称，资料数量、group_id、时间、相对顺序不变；取消改名无变化。

## AC-014 — 删除分组完整转移

需求来源：PRD §3.3、§6；OpenSpec bookmark-groups / Atomic group removal。

前置条件：正查看有多条收藏的分组且带关键词。

操作：阅读后果和当前影响数量，先取消，再确认删除。

预期：确认前明确只删组且全部收藏转未分组；取消保持原状；成功全部转移、总数不变、更新时间正确，切至未分组并保留关键词和有效页。

## AC-015 — 删除分组影响变化和原子失败

需求来源：PRD §3.3；OpenSpec bookmark-groups / Changed impact or failure。

前置条件：两个本轮上下文可以修改同一 A 账号测试组。

操作：确认窗口打开后另一上下文增加收藏，再确认；另外通过隔离 PostgreSQL 回归触发事务失败。

预期：影响变化不能沿过时数量静默删除；提示重新检查最新后果；真正失败完整回滚，不能部分转移或丢失资料。

## AC-016 — 当前页选择与取消

需求来源：PRD §3.4；OpenSpec bookmark-batch-organize / Current-page selection and recovery。

前置条件：至少 11 条当前条件资料。

操作：单选、当前页全选、部分选择；改变关键词、组、页码、浏览器历史；取消选择。

预期：数量/全选与半选表达正确，全选仅当前页；条件变化及取消清空选择，不能选择仍在加载的旧页；零选择无可执行移动，取消不写入。

## AC-017 — 批量移动、同目标与计数

需求来源：PRD §3.4；OpenSpec bookmark-batch-organize / Valid mixed-source move。

前置条件：选中多条且其中一条已在目标组。

操作：移动到目标自定义组，再验证全为同目标的移动和移至未分组。

预期：只改变实际选择与需改变归组的项；同目标项时间保持；实际改变项共享更新时间；无重复收藏，计数刷新且成功清空选择。

## AC-018 — 批量失效对象与失败保留

需求来源：PRD §3.4；OpenSpec bookmark-batch-organize / Unavailable or foreign object。

前置条件：当前页选择包含一条随后由第二测试上下文删除的项。

操作：删除一个源或目标后提交批量移动，刷新确认仍有效的选择，再进行有效重试。

预期：任何失效/外来对象导致整体拒绝且无部分移动；明确失败后仅保留仍可操作的当前页选择；没有资料损失或隐私泄露。

## AC-019 — 双账号 API 权限

需求来源：PRD §3.5；三个 OpenSpec 的 ownership 场景。

前置条件：A/B 各自通过真实 API 创建资料和分组，持有各自 token。

操作：使用 B 访问 A 的详情、更新、删除、归组和批量源/目标；尝试查询 A 的 operation 回执。

预期：所有资源按当前账号隔离；不能读取/修改/移动/删除他人对象，不通过错误披露私有内容；混合批量无任何部分写入。

## AC-020 — 换账号与迟到响应

需求来源：PRD §3.5；OpenSpec bookmark-core / Switch account during request。

前置条件：A 有打开的草稿和被延迟的读/写响应。

操作：A 退出后登录 B，再释放 A 的迟到响应；检查页面、选择、弹窗、恢复记录与缓存。

预期：不能显示 A 的资料或提示到 B；旧响应不更新新会话，私有列表、草稿和选择不会跨账号泄漏；恢复上下文绑定账号。

## AC-021 — 加载与三类空态

需求来源：PRD §4。

前置条件：新账号、空分组、无匹配搜索分别独立建立；只延迟真实列表响应。

操作：查看初始加载、首次无收藏、空分组及搜索空结果。

预期：加载不伪装清空；各空态说明原因，分别提供添加或修改/清空搜索等适用操作；保留必要上下文。

## AC-022 — 加载失败与已保存但刷新失败

需求来源：PRD §4；OpenSpec bookmark-core / Save failure and refresh failure。

前置条件：当前上下文可做明确标记的网络故障注入。

操作：首次 GET 失败后重试；有旧资料时刷新失败；真实保存提交成功后仅让后续 GET 失败。

预期：首次失败提供重试；刷新失败保留旧内容并说明未更新；保存已成功时不能显示为保存失败或诱导再次保存。

## AC-023 — 明确写入失败与防重复

需求来源：PRD §4；OpenSpec bookmark-core / Durable operation recovery。

前置条件：真实有效目标及合法业务校验错误样本；对网络可仅延迟。

操作：提交字段/业务明确错误并纠正；在 pending 期间连续点击或 Enter；重放同 key 同内容与冲突内容。

预期：错误保留输入/有效选择且恢复可操作；pending 有反馈并阻止重复意图；同 key 同内容不重复写入，不同内容冲突不能覆盖原结果。

## AC-024 — 结果未知与 resolve

需求来源：PRD §4；三个 OpenSpec 的 unknown / resolve 场景。

前置条件：仅在本轮请求中保留真实 Idempotency-Key；可控制请求转发及响应丢失。

操作：分别制造已提交但丢响应、resolve 先于原写入两种时序；覆盖收藏、分组和批量写入，重新加载后查询恢复记录。

预期：unknown 不等于失败或成功；保留原意图/可恢复上下文，禁止重复/冲突写；查看最新结果使用同 key resolve；已提交不重复，not_executed 阻止迟到原写入；刷新不承诺保留内存字段草稿。
