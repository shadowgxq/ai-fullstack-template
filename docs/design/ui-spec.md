# Web UI 规范

本页适用于 `frontend/` 的 React/Vite Web。微信小程序通用规则见 [移动 UI](mobile/ui-spec.md)，智能衣柜的业务布局见 [业务移动 UI](mobile/wardrobe-ui-spec.md)。本页维护视觉意图与布局关系；Token 选择与设计同步见 [Token 政策](tokens.md)，资产见 [设计入口](README.md#资产登记)。业务行为由使用方产品需求和服务契约定义。

## 视觉方向

Signal Teal 只保留 Light / Dark 两套配色，共用尺寸与组件。强调可读性、清楚的任务层级和明确操作；一个操作组通常只有一个主操作。图标辅助理解，不能代替名称或关键反馈。sans 用于界面与中文内容，mono 用于技术标识；字体与运行接线见 [主题指南](../engineering/frontend/guides/theming-and-i18n.md)。

## 信息与排版

页面、区块、卡片、正文与辅助说明使用已有文字角色；关键错误、动作和结果不降为辅助文字。连续阅读按内容需要使用已有字体尺度，不为未实现角色预建 Token。标题突出任务和对象，主次操作有明确层级。

内容增长时自然撑高；长中文/英文、字体回退和放大文字的行为检查归 [UI 状态](../engineering/frontend/standards/accessibility-and-ui-states.md)。不使用缩小字体或整页缩放消除拥挤。

## 布局与宿主

内容最大宽、区块节奏和容器 Padding 优先选择已有语义；多列布局按最小可读宽重排，窄屏表单单列。画布宽度是比较条件，高度只用于取景，不限制真实页面内容高度。

智能衣柜的小程序业务规则见 [业务移动 UI](mobile/wardrobe-ui-spec.md)，不由本页的 Web 宿主与组件规则约束。

模板 Web 页面在各自实现中组合 `AppShell` 与内容容器，没有统一 `.page-container`；不要根据规范臆造 import 或工具类。顶栏和内容的实际对齐/断点需核对相关源码，顶栏尺寸以实际宿主实现为准，见 [路由与宿主](../engineering/frontend/architecture/technology-options.md#路由与宿主)。

模板 Web 的控件几何与命中范围分别考虑，先用真实组件 API；其安全边缘使用浏览器 `env(safe-area-inset-*)`。小程序的安全区和宿主适配按移动规范处理。触控、局部宽表滚动、缩放与溢出要求归 UI 状态。

系统/浏览器 UI、应用壳与页面内容分开归属。时间、电池和浏览器工具栏不由页面重绘；应用标题、返回、导航由真实宿主或布局承担。模板示例仍是 Web；智能衣柜的平台以 PRD 为准，不依据画布外观判断运行时。

## 组件与状态

选择、分层和抽取按 [组件治理](../engineering/frontend/components/components.md)；能力与 API 核对 [清单](../engineering/frontend/components/component-inventory.md) 和源码。表单、ARIA、键盘、焦点、对比度与减少动态效果只在 UI 状态维护。

公共控件按实际维护单元组织可独立查看的规范区域，展示必要变体、状态及少量用法；不把大量无关控件塞入同一展示板，也不为展示容器建立可复用主组件。展开态应表达真实浮层内容，只有触发框不能代表 Select 已展开。公共库中的用法示例使用普通 Frame；需要展示模板页面时放在 Examples 区域，不新增主组件。使用方的实际业务布局与导航由其消费稿维护，直接引用可用公共能力。

状态要可辨识且不压过主任务；装饰分隔、必要控件边界与焦点各自承担不同用途，同色不构成可互换依据。

模板认证、分享和导航以现有能力为准：未启用的 provider/验证码/改密不出现在默认能力示例中，分享操作按真实浏览器能力显示。复制或调用成功不能自动解释为已发布或已投递。

## 维护与验收

共享视觉或契约变更需核对直接消费者；设计与代码的同步见 [Token 政策](tokens.md#设计与代码同步)。适配与验证接口见 [交付约定](design-handoff.md)，未检查的主题、宽度或真实交互保留未验证范围。
