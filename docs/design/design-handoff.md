# 设计交付约定

本页提供模板的平台与适配参数。任务路由见 [前端导航](../engineering/frontend/README.md#任务路径)，通用读取、制稿、实现与验证动作由同一 Skills 来源的 [设计工作流](../../.agents/skills/DESIGN-WORKFLOW.md) 和四个正式入口维护。

## 适用项目

目标包为 `frontend/`，React/Vite Web；手机画布是触控布局。框架、Provider、路由和宿主以 [技术基线](../engineering/frontend/architecture/technology-options.md) 与真实源码为准。

读取从 [根 AGENTS](../../AGENTS.md)、[文档地图](../README.md)、[frontend/AGENTS](../../frontend/AGENTS.md) 进入。新页面和关键交互按任务路径准备设计；已有适用稿复用，轻量修改沿用同一套视觉、Token、组件与状态规则。

## 来源与目标

[资产登记](README.md#资产登记) 定位公共库、消费稿和预览。记录实际文档、Frame/选区、主题、状态、逻辑宽度、保存版/编辑器版和可用修订；使用节点 ID 前回读，路径和截图不能证明当前连接。

代码目标由真实页面和路由定位。业务需求由使用方 [产品入口](../product/README.md) 与 [契约](../contracts/README.md) 提供，模板例稿不构成新业务 PRD 或已批准实现。

## 组件与 Token

按 [组件治理](../engineering/frontend/components/components.md) 选择；[组件清单](../engineering/frontend/components/component-inventory.md) 只负责发现/可见性，实际 import 必须核对 export、类型与必要调用点。Pen 变体、模式和 Frame 不要求逐一生成 React 组件。

交接区分设计当前所在文件、目标归属和实际代码入口；按 [公共层准入](../engineering/frontend/components/components.md#公共层准入) 判断，不从 `shared/ui` 路径、跨页使用或外观直接推定公共归属。默认两份设计文件的职责见 [资产登记](README.md#资产登记)。复杂组合和归属未明确的内容先放业务消费稿，复用已有控件，不为设计归属调整创建对应 React 包装或搬迁源码。

主组件、用法示例与实际页面按 [维护单元](../engineering/frontend/components/components.md#主组件用法与页面) 区分。公共稿可用 Label + Input 或内容 Skeleton 解释用法，示例容器保持普通 Frame；完整业务流程与页面在消费稿中表达。交接不把控件所在的展示板或组件目录分类当作公共准入证据。

归属同步须在设计修改获授权后执行：先核对主组件与直接实例依赖，再在业务消费稿承接组合并更新引用；公共库只保留符合准入的控件与必要状态示例，不能反向引用消费稿。同步后回读导入、主题、实例覆盖和受影响画面，再更新清单中的实际位置；规范中的目标归属不代表节点已经迁移。

Token 按 [选择政策](tokens.md) 使用，值读 [global.css](../../frontend/src/shared/styles/global.css)。交接记录设计节点/角色 → 实际组件或组合 → API/语义 Token → 主题和适配。支持属性用真实绑定，解析值及 `metadata.token-map` 单独记录限制。

设计字体投影为 Noto Sans SC / IBM Plex Mono，Web 保留已有 sans / mono 和系统 fallback。设计字体可用不证明运行时字体已加载。

基础 Button 和菜单项使用最小高度、Token Padding 与自然换行；纯图标按钮保持方形尺寸。设计稿表达默认几何和允许的内容增长，字体放大、触控几何及必要边界仍按真实消费者核验，规范要求不等于浏览器验收已完成。尺寸在当前工具中采用 CSS 解析值并记录 `token-map`；opacity 使用 CSS 比例到画布百分数的投影，均不冒充自动 CSS 联动。

## 布局与宿主

应用标题、导航、设置与账户由 AppHeader / AppShell 承担；页面负责自己的内容。当前 AppShell 的 props 和路由用法需核对源码；不能按手机稿统一删除应用顶栏。系统时间、电池和浏览器 chrome 不重绘。

模板示例只组合已有能力：LoginModal 是当前页面上的认证浮层，`/login` 重定向并打开它；ShareDialog 消费调用方提供的 poster，窄屏可采用实际实现的底部浮层。不可把画布中的反馈当作真实请求或浏览器能力证明。

比较时固定主题、状态、平台、逻辑尺寸与已批准适配，注明整页、内容区和宿主边界；不裁剪隐藏重复顶栏、缺失区块或溢出。

## 深浅主题的设计表达

采用**一份结构、两套主题值、按需展示、双主题验证**。Light / Dark 共用语义 Token 名称；颜色按主题取值，未变化的几何与交互共用。默认维护一套主组件和页面结构，不分别维护 Light / Dark 独立主组件，也不为主题新增设计文件。

| 对象 | 默认表达 | 需要额外展示时 |
|---|---|---|
| 公共颜色规范 | 紧凑展示 Light / Dark 的背景、文字、边界和状态配对 | 不以全量页面复制代替颜色契约 |
| 基础控件与通用交互 | 一套主组件及必要状态；主题由变量解析 | 用同源实例展示关键状态与颜色配对，不要求每个变体各铺两份 |
| 普通业务页面 | 一份主稿，在同一结构上切换主题核验 | 为评审导出另一主题截图或保留必要对照实例，不默认长期复制完整页面 |
| 主题敏感内容 | 对差异部分明确设计与验证 | 图片/Logo 换版、图表/行情色、渐变、透明叠层、阴影/边框或确有结构差异时，保留必要双主题表达并说明原因 |

同源实例的双主题对照不算两套组件实现，但也不要求每个页面、状态、宽度都常驻两份画板。默认展示主题沿用当前任务或项目基线；确有主题差异时优先局部变体或资源映射，共用其余结构。

Token 绑定不等于主题正确。受影响组件与页面需核对两主题的有效值、实例覆盖及实际渲染，重点检查文字/背景、边界/焦点、禁用与选中、透明合成和图像可辨识性。重复组合可复用未变化的基础契约证据，页面独有背景、资产和叠层仍需检查；代表样例通过不能声称未查看的页面也通过。按实际主题、状态和范围记录结果，缺另一主题证据时保留 `not_run`，不以减少展示板缩减验证要求。

已有双主题画板和预览是当前资产记录，不代表新任务必须继续成对产出。合并或删除须在设计修改范围内先核对引用、覆盖和历史证据；仅修改规范不执行画布清理。只读任务不擅自切换主题，设计渲染也不代替代码或设备交互验收。

## 验证接口

命令只在 [根 Makefile](../../Makefile)、[公共验证范围](../engineering/common/README.md#验证范围) 与 [前端 README](../../frontend/README.md) 维护。Lint/类型检查不能自动证明组件复用、Token 语义或设计一致性。

`.pen` 定位、读写、库导入、保存、截图与回读使用实际 Pencil MCP / `pen interactive` 能力，不使用 Computer Use 或普通文件工具编辑序列化内容。库须通过正式创建/导入机制建立连接，普通复制和改后缀不构成库复用；持久化后重开消费者检查主题及覆盖。

设计结构、Token/组件引用与实际渲染分别记录 `passed | failed | not_run` 及范围；代码、浏览器/键盘/网络行为和人工验收另行报告。没有实际查看图像时视觉为 `not_run`，没有基线时不声称设计还原通过。

## 交接与读取

正式技术方案前，在现有设计文档位置维护同一份需求级设计记录，引用已确认 PRD，并定位真实 Pen 文件/Frame/修订、必要状态/主题/视口、组件与 Token 映射、实际检查及接受范围。此时无需 Change/task IDs；就绪条件与代表页决定沿用 [设计工作流](../../.agents/skills/DESIGN-WORKFLOW.md#设计就绪与技术反馈)。未实现或无法访问的能力、主题、映射和消费者如实保留。

技术方案实际读取该记录与相关设计节点，再确定实现契约；不可行交互或契约冲突返回同一设计来源做最小修订，产品行为变化先确认 PRD。后续 Change 的 `design.md` 引用同一记录、修订和本任务 Frame/状态，UI 任务在 `tasks.md` 绑定 `design-to-code` 的范围；不复制设计正文或新建平行任务状态。设计接受不代替代码验证与最终人工产品验收。

四个正式 Skill、共同协议和必要引用必须来自同一完整来源。Pencil 菜单选用的自定义 Skill 与 MCP `read_skill` 工具说明是不同上下文，均不自动取得项目读取权。不可访问时补本次必要原始规范/源码和版本，不保存长期精简副本。
