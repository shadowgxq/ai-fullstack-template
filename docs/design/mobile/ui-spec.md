# 移动端 UI 与适配规范

适用于 `miniprogram/` 的微信小程序。视觉沿用 Signal Teal；移动端信息层级、交互、尺寸与宿主规则独立于 Web。Token 值与归属见 [移动 Token](tokens.md)，当前实现范围见 [组件清单](../../engineering/miniprogram/components/component-inventory.md)。本页是设计/实现约束，不代表所有条目都已制稿或真机验收。

## 页面与导航

**手机优先、单手可达、一个操作组一个主操作。** 默认原生 navigationBar + 原生 TabBar；正文从微信提供的可用视口开始，不重画时间、电池、状态栏或右上胶囊。顶栏只保留页面定位与必要操作，不把 Web Logo、完整导航菜单、账户操作、搜索和筛选全部塞到顶部。

跨业务一级目的地才进入 TabBar，流程动作不作为 Tab；页面内筛选/切换与全局导航分开。当前模板三个 Tab 是组件演示入口，业务接入时按真实目的地替换，不把示例导航冻结成产品要求。次级页面保留原生返回，不同时绘制两套返回按钮。

只有需求明确要求品牌头部或沉浸场景时才采用自定义导航；此时必须使用实际窗口与胶囊位置测量，区分 px/rpx，并处理前后台恢复及窗口变化。不能用固定 44/88px 猜测状态栏+导航总高；自定义导航不属于当前默认实现。

## 布局与单位

代表稿 **375 逻辑 px 宽**，高度随内容增长。组件不锁整页高度，不靠截图固定尺寸压缩内容。正常视口使用左右留白、单列流式布局；卡片之间留白大于内部元素，减少装饰边框和重复标题。

当前工程关闭 Taro 自动 `pxtransform`：字号、行高、触控最小尺寸、边框与间距使用逻辑 px，宽度用 `%/flex/min/max`；只有应按屏宽同比缩放的媒体几何才显式使用 rpx。375px 稿与 750px 稿不能混用原数值；`Taro.pxTransform` 只用于明确需要屏宽比例的值，不能再次转换微信 API 返回的 px。

窄屏先换行、纵向排列次要操作、收敛非必要内容，不缩小字体/触控区。较宽窗口只居中限宽（当前内容最大宽由 Token 提供），不拉伸成多栏后台，也不复用 Web 的 1336px 正文最大宽。局部数据确需横向滚动时只允许该区域滚动，不能让整页横向溢出。

## 安全区、滚动与键盘

页面滚动为默认，避免不必要的整屏 ScrollView 和内外双滚动。无 Tab 的页面按 `env(safe-area-inset-bottom)` 保留底部空间；原生 TabBar 已拥有底部安全区，正文不再累加。横向安全区由宿主 inset 处理，不写死设备型号。

底部固定主操作仅在高频长流程中按需增加，必须预留与真实栏高相等的内容占位，且只有一个层级负责 inset。键盘弹出时操作栏避让/收起策略须在设计中说明，不能让固定按钮压住输入。当前模板没有固定底栏，登录采用自然滚动与 Input 的 adjustPosition/cursorSpacing。

## 字体与触控

正文优先 16px，辅助文字 14px；关键结果和错误不降为微小灰字。标题、字号与无单位行高配对，使用系统中文字体 fallback，不为小程序加载桌面字体资源。长中文/英文自然换行；放大文字时允许控件和卡片增长，不以单行固定高度截断重要文本。

本项目自定义操作默认至少 **48×48 逻辑 px** 的可触区域，图标视觉可以更小但命中区不能缩小，相邻目标保持可辨间距。这是项目的保守触控基线，不是把 WCAG 的最低要求解释成 48px；[WCAG 2.2 Target Size Enhanced](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html) 的 44px 方向用于参考，原生宿主控件按平台边界处理。

## 组件、交互与状态

| 内容 | 移动端约束 |
|---|---|
| Button | 主/次/危险分层、清晰 pressed、实际 disabled/loading；没有 hover 也能完成任务 |
| 表单 | Label 常驻、字段错误就近且保留输入、匹配键盘；placeholder 不替代标签 |
| 菜单/浮层 | 少量动作优先原生动作面板；复杂选择按需设计 BottomSheet/独立页，不能把桌面 Popover 缩窄直接使用 |
| Loading | 骨架匹配内容大结构；重复提交由操作控件阻止，避免整页闪烁与无限装饰动画 |
| 空/错误 | 说明对象、原因或下一步；取消与失败分开，不把未知当零结果 |
| 成功反馈 | 对应真实副作用完成；本地示例、选图、复制不等于上传/发布/交付 |

错误不仅靠红色，选中不仅靠颜色；提供文本或形状状态。现有暖色 warning 值保留来源，但不会为了展示色板给常规提示涂大块黄色；中性说明使用表面/辅助文字，危险使用明确错误语义。动画以即时反馈为主，模板骨架默认静态；无 hover/focus 依赖的隐藏入口。

## 设计交付边界

沿用全局 `ui-ux-delivery / pencil-design / design-to-code / design-qa`，先确认微信平台、目标包、原生/自定义宿主和代表性状态。先完成代表页与关键交互，再扩展其他页面；不自动生成整套桌面稿。Web 稿只能提供配色/品牌参考，不能视为已批准小程序交付物。

当前公共 `.pen` 仅覆盖 Web，本次移动规范与代码不虚构新 Frame ID/库连接。业务设计需记录其实际源文件/Frame、单位、状态、平台与接受范围，验收按 [运行指南](../../engineering/miniprogram/guides/runtime-and-verification.md) 留真实证据，不默认启动浏览器/E2E。
