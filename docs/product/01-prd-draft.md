# AI 智能衣柜系统｜V1 产品需求文档

版本：V1.2｜日期：2026-10-19

## 1. 产品目标与范围

面向管理个人衣柜、需要日常穿搭建议的用户，提供衣物录入、管理和使用统计，并根据天气、个人偏好与实际穿着历史生成 AI 穿搭建议。目标是降低整理衣柜和选择穿搭的成本，提高现有衣物的可见性与使用效率。

产品为微信小程序，以手机端使用为主，采用微信登录。用户登录后管理自己的衣柜，多账号数据隔离，不提供衣柜共享或多成员协作；V1 不另行交付独立 Web 或 PC 页面。

核心流程：`录入衣物 → 整理衣柜 → 获取穿搭建议 → 确认实际穿着 → 查看历史与统计 → 支持下次推荐`。

### 1.1 V1 功能范围

| ID | 能力 | 用户结果 |
| --- | --- | --- |
| FR-001 | 手动录入、查看与编辑衣物 | 按选项录入衣物，属性可不填，可附图片 |
| FR-002 | 衣柜浏览、筛选与状态管理 | 查找衣物，管理可穿、暂不可穿及已归档状态 |
| FR-003 | 个人穿搭偏好 | 设置喜欢和避免的风格、颜色及场合偏好 |
| FR-004 | 实际穿着记录 | 确认、补录、查看、修正及删除误记录 |
| FR-005 | 衣柜与穿着统计 | 查看衣物数量、类别分布、穿着次数及使用趋势 |
| FR-006 | AI 穿搭建议 | 根据可用库存、天气、偏好及历史获得推荐 |

### 1.2 后续范围与非目标

FR-007 推荐反馈（喜欢/不喜欢）与 FR-008 图片 AI 自动分类、识别属于后续范围，不作为 V1 的交付和验收条件。

V1 不提供虚拟试衣、3D 建模、自动识别当天真实穿着、服装电商导购、社交穿搭、私有个性化模型训练、零售库存或团队仓储管理。

## 2. 用户流程与权限

1. 用户通过微信登录，进入自己的衣柜；未成功登录时不读取个人数据。
2. 手动按选项录入衣物，保存后可浏览、筛选和编辑。
3. 选择性填写穿搭偏好；按需获取小程序定位或手动选择城市。
4. 请求 AI 推荐，查看所推荐的库存衣物、理由及信息缺失说明。
5. 确认实际穿着，或手动补录历史穿搭。
6. 查看历史和统计；修正或删除误记录后，统计同步更新。

衣物、图片、偏好和历史归所属账号管理；其他账号不得查看或修改。未登录时不能访问个人衣柜数据。照片、偏好和穿着记录不公开。

主导航包含“衣柜、穿搭、记录”三个入口：衣柜负责衣物管理与录入，穿搭负责推荐及当前搭配调整，记录负责实际穿着历史并提供统计分析入口。小程序使用固定底部 Tab，不新增独立 PC 导航或页面。

顶部显示当前页面名称，预留微信系统胶囊区域；主页面的个人入口放在左侧，子页面提供返回。长期偏好放在个人页，一次性场景条件放在穿搭页。顶栏与底部导航固定，天气随内容滚动，安全区根据实际设备环境适配。

微信登录不要求填写用户名、密码或手机号；首次成功登录建立个人账户，再次登录进入同一微信身份的衣柜。失败或取消时保留重试入口，不显示已登录状态。头像、昵称可在个人资料中自愿填写，未填写时使用默认头像与“衣柜用户”，不阻止衣柜和推荐使用，不把微信登录当作自动取得头像昵称或位置授权。个人页提供资料、穿搭偏好、城市、日期时区及退出登录入口；退出后清除当前登录状态，不再展示个人数据。

## 3. 功能规则

### FR-001 衣物入库、查看和编辑

- 用户手动按选项填写主类别、颜色、季节/温度适用性、正式程度/场合及标签，可添加名称、图片和备注。
- 照片或名称至少提供一项；名称仅空白字符视为未填写，照片须已成功上传。类别、颜色、季节、场合、标签和备注均为可选，缺失值保持未知，不自动补为事实。
- 添加页默认显示照片、名称、分类和主要颜色；季节、场合、标签和备注归入默认收起的“更多属性”，收起不清空已填值。照片分别提供拍照和相册入口，取消或拒绝权限不丢失其他输入；V1 不暗示自动识别属性。
- 分类使用移动端选择弹层；颜色使用色块及更多颜色弹层，季节、场合和标签支持多选，标签支持自定义。新衣物默认可穿，后续通过详情管理状态。添加按钮固定在底部，与可滚动表单分区，最后一项可滚动至完整可操作位置；输入键盘出现时收起固定操作区，保留焦点字段可见，键盘关闭后恢复。
- 照片与名称均缺失时不创建记录，提示“请添加照片或填写衣物名称”，保留其他已填内容并定位到相关区域；上传或保存失败时保留输入供重试。
- 允许重复录入，V1 不提供自动去重。
- 保存成功后衣物出现在衣柜，显示内容与保存内容一致；失败时明确反馈并保留已填写内容供重试，不显示虚假成功。
- 编辑后查询及后续推荐读取最新有效属性；已经形成的穿着历史保持可追溯。

### FR-002 衣柜管理与可用状态

- 支持浏览衣柜、按类别及已填写属性筛选、查看和编辑衣物。
- 使用 `可穿`、`暂不可穿`、`已归档` 三种业务状态；只有可穿衣物参与推荐。
- 支持归档与恢复。V1 不提供衣物永久删除。
- 归档不删除已经发生的穿着记录。历史保留穿着时的衣物名称和类别，避免后续编辑或归档改变过去记录的含义。

### FR-003 个人穿搭偏好

- 支持设置喜欢和避免的风格、颜色、场合偏好，以及可选舒适度要求。
- 未填写偏好不阻止推荐，不声称已学习到用户喜好。
- 明确避免的选项作为排除条件；喜欢的选项、天气适配及近期重复情况用于推荐排序。
- 无候选满足排除条件时解释原因，不擅自放宽排除条件。未知属性不得当作已满足相应条件。

### FR-004 实际穿着记录

- 用户可以确认推荐中的衣物实际穿过，也可以手动选择已有衣物补录；每条记录包含穿着日期和一组衣物。
- 推荐、展示或收藏不自动形成实际穿着记录。只有用户确认的穿着事实进入统计。
- 同一天允许多条穿搭记录；同件衣物在同一条记录中只计一次。重复提交同次保存不产生重复记录。
- 日期按用户设置时区归属，默认 `Asia/Shanghai`；允许补录过去日期，不允许记录未来日期。
- 支持查看、修改记录及删除误记录；修改或删除后统计同步更新，不残留计数。
- 保存失败时保留已填写内容供重试，不显示虚假成功。

### FR-005 统计与说明

| 指标 | 口径 |
| --- | --- |
| 衣物总数 | 可穿与暂不可穿衣物数量之和，已归档数量单列 |
| 类别分布 | 统计衣物总数范围内的类别，未填写类别的衣物单列为未分类 |
| 穿搭次数 | 用户确认的实际穿着记录数量 |
| 单件衣物穿着次数 | 关联该衣物的实际穿着记录数量，同一记录内不重复计数 |
| 使用趋势 | 默认展示近 30 个自然日的实际穿着记录数量，日期口径与 FR-004 一致 |

历史穿着统计包含已归档衣物的既有记录。修改或删除穿着记录后按修正后的事实更新相关计数。

没有记录不代表没有穿过。统计使用“未记录穿着”“暂无已记录穿着”等表述，并说明所统计的记录时间范围，不将不完整历史解释为“从未穿过”。

### FR-006 AI 穿搭建议

**库存与输入**

- 仅使用当前用户衣柜中可穿的衣物，结合已填写属性、天气、已保存偏好、已确认的穿着历史及用户提供的临时场合需求。
- 根据库存推荐，数量与组合随库存变化，不固定一套，不预设必须包含的品类组合；不因缺少下装等某一品类一律拒绝推荐。
- 属性不完整时，使用已有信息给出可支持的建议，并说明无法判断的部分；不编造类别、颜色、保暖能力或衣物，不将属性填齐作为使用流程的前提。
- 历史或偏好为空时仍可推荐，说明相应信息缺失，不推断不存在的真实历史或喜好。
- 场景条件可选择通勤、休闲、约会或不限场景；选择只影响当前推荐条件，不覆盖长期偏好。通过 Bottom Sheet 选择。
- “换一套”重新请求整组推荐；点击衣物可选择本人可穿库存替换该单品，其余已选衣物保留。换整套或替换单品都不自动形成实际穿着记录。

**位置与天气**

- 默认天气城市为杭州；已有保存城市时优先使用保存值。用户可主动定位或手选其他城市，成功后使用新的选择，不自动申请定位。定位不可用、失败或用户拒绝授权时保留当前城市，未有其他有效选择时使用默认杭州，不因定位失败阻塞衣柜及推荐流程。
- 使用所选位置或城市当天的天气，展示适用地区、日期及天气更新时间。
- 天气请求失败时明确说明天气缺失，继续提供不依赖天气的建议；不得伪造天气事实。默认杭州明确作为默认城市展示，不声称是用户定位结果。

**输出与异常**

- 推荐展示具体库存衣物及选择理由，并说明天气、属性、偏好或历史缺失带来的限制，不将局部推荐描述成完整搭配。
- 推荐依据默认在首页直接展示天气与时效、已填写偏好、历史及取舍说明，不要求用户再点击展开或收起；缺失信息如实标注。内容超出首屏时在中间内容区自然滚动，不缩小图片或字号，底部操作与主导航保持固定。首页最近穿着只保留简要入口，完整历史与统计位于“记录”。有库存时不常驻大幅衣物录入按钮，无库存时提供录入引导。
- 天气舒适性、色彩协调、喜欢的风格及避免近期重复作为排序因素；存在取舍时给出说明，不承诺绝对准确的穿着效果。
- 输出须检查衣物归属、状态及明确排除条件；无可用库存或无候选满足排除条件时说明具体原因，不编造衣物或擅自放宽条件。
- AI 服务失败时给出明确失败反馈，支持重新请求；失败或取消不产生穿着记录，也不修改衣物数据。

## 6. 产品边界与限制

- 手动录入与属性缺失会限制推荐质量，推荐说明应反映实际可用信息，不承诺准确率或个性化效果。
- 穿着历史依赖用户主动确认，统计仅反映已记录事实。
- 设备位置可能与实际穿搭地点不同，用户可手动选择目标城市。
- 本文定义目标行为及验收要求；实际实现、验证结果及产品验收记录由交付记录维护。
