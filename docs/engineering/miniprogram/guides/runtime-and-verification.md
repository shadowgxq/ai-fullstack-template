# 小程序运行与验收

安装、配置和启动命令只在 [服务 README](../../../../miniprogram/README.md) 维护；本页定义证据边界。微信开发者工具采用支持当前基础库的稳定版本，目标基础库以 **3.0.0 及以上**为本端接入基线；不宣称覆盖旧微信、所有 iOS/Android 或所有 WebView 实现。

## 验证范围

| 变化 | 默认定向检查 | 不由它证明的内容 |
|---|---|---|
| 文档/导航 | 根 docs、相关链接/规则测试 | 代码运行和视觉 |
| 请求/状态/存储 | 类型、Lint、相邻单测 | 真实 Backend/微信联通 |
| 配色/Token | 双主题提取、生成漂移、消费样式检查 | 真实设备颜色、对比/可读性完整验收 |
| 配置/依赖/组件 | 上述检查 + 微信生产构建 + check:dist | 原生 API、键盘、触摸与真机 |
| 新业务关键流程 | 涉及提供方和直接消费者，按验收调用真实服务 | 未执行的终端/权限/发布状态 |

`tests/taro-mock.ts` 仅在 Vitest alias 下生效，生产构建不导入 mock；根没有重复的小程序测试状态机。每条结果区分 passed/failed/blocked/not run，写当前 PR/change，不新增长期执行流水文档。

## 首次人工运行

在开发者工具导入构建目录配置后，确认衣柜、穿搭、记录三个业务导航入口，以及个人、设置和表单页面的返回、主题偏好与正常/空/错误展示。业务页面使用自定义导航，不注册原生 TabBar；辅助示例是普通页面。按适用设计检查代表尺寸与窄屏，关注单列、自然高度、按钮可点、文本不遮挡，PC 微信仅检查内容居中限宽。

登录页重点检查键盘打开/关闭、最后字段与提交按钮可达。业务顶栏与底部导航按自定义宿主实现，胶囊由微信负责；检查顶部避让、底部安全区和固定操作，避免重复留白。辅助页面按自身导航配置检查，不将业务页当成原生 Tab 页。媒体选择检查取消、授权拒绝和本地预览，上传需有真实端点才验收。

Backend 联调使用专门测试账户，验证登录→me→退出→旧 Token 拒绝，并验证 401 与 503 不混淆。`/health` 成功仅表示服务存活，不代表数据库/Redis/认证链路就绪；依赖检查与数据流依据 Backend 的 `/ready` 和实际业务行为。

真实 AppID、可访问的合法域名、微信隐私配置、开发者工具与至少目标 iOS/Android 微信设备未就绪时，记录具体缺项。CLI 构建不自动上传或触发审核，不以 mock 冒充微信 code2session、用户授权或产品验收。
