# 公共代码质量

适用于各端新增或修改的代码。只维护跨语言的命名、注释、复用与正确性原则；语言写法和分层落点由专项规范补充。纯文档或配置任务只读相关章节，不要求通读所有工程文档；既有代码只处理受影响范围，不借规范升级全仓改名。

## 变量与函数

- 名称表达对象或动作：值用名词，函数用动作；集合用复数，映射体现键，例如 `usersById` / `users_by_id`。局部上下文明确的 `item`、`key` 可以保留，不用 `data1`、`temp2` 隐藏业务含义。
- Boolean 优先使用肯定的 `is`、`has`、`can`、`should` 语义；遵守语言大小写。DOM、第三方 API、数据库字段和既有公开契约保留原名，不为命名喜好添加转换层。
- 数值说明单位与语义，例如 `timeoutMs` / `timeout_ms`、`retryCount` / `retry_count`；时间明确时区，金额明确币种、精度和舍入边界，比例区分 0–1 与百分数。
- 默认缩小作用域、减少可变状态；可从事实源推导的数据不维护第二份可写副本。常量归语义拥有者，不把业务选项堆进全局 `constants`。
- 有业务含义或多处共享的数值/字符串提为命名常量；有限状态用受约束类型。不把所有 `0`、`1` 和固定样式值机械抽成常量。
- 函数聚焦一种职责，输入、输出和副作用可辨认；纯计算与 I/O 分开。拆分依据责任和变化原因，不设统一行数指标，不创建只有透传的 class/helper。

## 注释与说明

注释补充代码无法表达的**原因、约束、单位、并发或兼容边界**；接口说明补充调用契约、重要错误与副作用。先改进命名与结构，再补注释，不逐行翻译代码。

```python
# 不足：这里只复述下一行代码。
# 提交事务。

# 有用：解释不能改变的执行顺序。
# 命令与 Run 必须一起提交，否则 Worker 可能领取到不存在的 Run。
```

公共接口存在非显然的空值、单位、异常、授权或恢复语义时，用简短 docstring / JSDoc 说明；自解释的私有小函数不强制写模板注释。注释沿用所在模块语言，修改逻辑时同步修正或删除失效说明。

兼容 workaround 写明原因与移除条件，必要时关联 issue/ADR；TODO 必须有可定位事项与完成条件。删除已废弃代码，不用注释块保存历史，不写对话、操作流水或“已经优化”等交付记录。

## 复用与抽象

先查相邻实现、公开出口和能力清单，再按“直接复用 → 兼容扩展 → 就近新增 → 提取共同边界”选择。复用判断是语义与契约相同，不是代码长得相似。

| 发现 | 处理 |
|---|---|
| 相同职责、契约、生命周期 | 使用现有实现；缺小能力时兼容扩展，并验证原调用者 |
| 仅展示/计算相似，业务规则不同 | 分别保留业务；只提取真正相同的样式、纯函数或基础交互 |
| 新的单场景职责 | 就近实现；多个真实稳定消费者出现后再评估提升共享层 |
| 为复用需要许多模式开关、回调或反向依赖 | 停止泛化，重新划分边界；不预建万能 BaseService / BaseAgent |

既有模板公共能力不因当前只有一个演示调用者而删除。修改共享 API 要查真实调用点和直接消费者；不复制第三方库已提供的能力，也不绕过模块公开边界。两端共享规则不等于共享运行时代码，不能通过跨服务 import 复用 ORM、配置或连接。

## 正确性与错误

- 实现前确认现有符号、参数、返回类型、锁定版本和调用者；不凭记忆编造 SDK 方法、组件 props、接口字段或已完成能力。外部文档与安装版本不符时先核对，不直接升级依赖来迁就示例。
- 在输入边界校验不可信值；内部通过明确类型传递。类型断言、类型注解和 schema 通过不等于运行时有效、权限正确或事实准确，不能用断言掩盖缺失数据。
- 区分缺失、空集合、数值零、失败与未实现；默认值只能表达约定的缺省语义。不得将异常转成成功、空数组或零值，禁止生产路径静默切换演示数据。
- 每项可变状态有明确拥有者；异步操作考虑重复、乱序、取消和迟到结果。写操作确认事务/幂等边界，远端副作用不能靠本地类型或锁保证一次执行。
- 只在能恢复或正确转换的边界捕获异常；保留内部错误链，外部返回安全错误。重试只由明确边界控制，不让 SDK、业务层、UI 各自重试而放大副作用。

## 变更复核

只检查本次影响面，证据记在当前 PR、change 或 repair，不新增平行进度或长期检查报告。

| 检查点 | 最小证据 |
|---|---|
| 行为与边界 | 验收/契约对应到实现；主要失败分支和不变量有相邻测试 |
| 复用与依赖 | 现有入口和直接调用者已核对；新抽象确有职责，未引入反向依赖 |
| 数据与副作用 | 空值、未知值、权限、重复/乱序、失败恢复按实际风险检查 |
| 类型与版本 | 受影响端静态检查；跨端变更补提供方与直接消费者，不以 mock 证明联调 |
| 交付准确性 | 记录实际命令和 passed / failed / skipped / not run；未运行不写通过 |

测试优先覆盖用户可观察行为、数据转换和关键分支；不要为常量、纯文案或简单透传机械补用例。已知回归不能通过删除断言、放宽类型、屏蔽规则或改用假数据绕过。具体命令按 [验证范围](README.md#验证范围) 选择；格式/链接检查不证明业务正确，人工语义 review 不由 CI 替代。

参考 [Google Code Review](https://google.github.io/eng-practices/review/reviewer/looking-for.html) 的设计、复杂度、命名、注释与测试检查方向。上述复用顺序、命名细则和证据要求是本仓库的裁剪约定，不是外部规范的完整复制。
