# 前端初始化与上游同步

本页分别维护复制模板后的项目初始化与前端上游代码同步。项目初始化包括模板产品化清理和视觉重建；它与上游同步独立，不因复制模板、调用初始化入口或新增业务而自动同步上游。

## 复制模板后的项目初始化

### 入口与范围

项目级 [project-init](../../../../.agents/skills/project-init/SKILL.md) 是显式执行入口，规则只维护在本节。它不安装环境、不清空数据、不更改技术架构，也不替代通用设计 Skills。

### 模式选择

仅有以下两种执行模式：

| 类型 | 名称 | 执行范围 |
|---|---|---|
| `cleanup` | 清理模板展示内容 | 默认将模板收敛为业务项目的最小起点，清理模板展示页面、导航、路由及关联示例资产和引用；保留真实业务、认证、公共组件和最小运行结构，沿用当前公共 Pen、Token 与视觉风格；明确限定范围时仅处理该范围 |
| `rebuild` | 重建视觉体系 | 按新方向更新 Token、受影响组件样式、公共 Pen 及实际消费者；验证替代内容后清理被替代的旧资产，保留工程架构和交互契约 |

执行初始化时，用户未指定模式就先询问：“请选择 `cleanup`（清理模板展示内容，保留基础能力与现有风格）或 `rebuild`（重建视觉体系）。”选择前只做只读盘点，等待回答，不默认沿用、不代选模式，也不把盘点报告为初始化完成。当前请求或同一任务上下文已明确指定类型，或以自然语言明确选择了对应模式时直接执行，不重复询问。仅分析、说明或查看状态的请求保持只读，无需选择执行模式。

例如，`$project-init cleanup` 使用默认产品化清理范围；`$project-init cleanup，仅清理旧模板设计示例和关联预览，保留公共库` 将范围限定为设计资产，不修改页面代码；`$project-init rebuild，改为暖白背景、橙色强调的视觉体系` 选择重建模式。模式选择不等于授权清空目录：`cleanup` 仍需依据实际依赖明确清理对象；`rebuild` 沿用已给定方向，缺少方向时先澄清再执行依赖该方向的替换。

两种模式均按授权范围执行。明确选择默认 `cleanup` 或要求模板产品化清理，即包含模板展示页面及关联导航和路由，无需逐页另行授权；用户指定的保留项和更窄范围优先。`rebuild` 不自动包含全部展示页面清理。只改颜色、字体等局部视觉要求按 [前端任务路径](../README.md#任务路径) 定向修改，不另设第三种模式或扩成全面重建。普通业务继续按该路径增量设计，不反复初始化。没有策略配置文件、多套长期模板分支或额外审批流程。

### 产品化清理边界

按实际用途、调用关系和已确认需求分类，不以“当前 PRD 未提及”或页面名称作为删除依据。模板展示内容已被改造成真实业务时按真实业务保护；用途存在重大歧义时只澄清该对象，继续处理范围明确的部分。

| 对象 | 默认处理 |
|---|---|
| 当前需求及已有真实业务 | 保留；不删除其他业务模块、数据或执行记录 |
| 登录、会话、权限及必要账号入口 | 保留，核对认证流程与返回目标 |
| 公共组件、公共 Pen、Token、主题及语言机制 | 保留；移除展示页不等于删除底层能力，不顺带裁剪组件库 |
| Router、Provider、错误页与 404 | 保留最小运行结构及真实业务需要的路由 |
| 模板介绍、组件展厅、主题演示及其详情页 | 清理页面、专属导航、路由及直接引用；如 Overview、Components、Theme，需先确认其实际用途 |
| 模板品牌占位、示例内容与关联预览 | 按已知产品信息替换或移除；未知时保留中性最小文案，不虚构品牌与功能 |

已有明确业务首页时，`/` 进入该页面或重定向到其稳定路径，同步 Logo 与登录后的默认落点，保留有效的业务深链回跳。尚无业务需求时，`/` 保留最小可运行页面，不生成演示业务。只有一个业务入口且没有独立导航用途时，移除冗余导航，保留必要的应用标题、账号及设置，并调整移动端布局。

适合在首次业务设计前执行；已有业务后补执行时，核对应用壳、设计和技术方案是否误带入模板展示内容，在本次授权内同步直接受影响的当前引用，不改写归档历史。复用应用壳不意味着接受其全部导航，模板现状不能单独作为产品需求依据；已明确确认且与清理目标冲突的业务决策先澄清。

### 执行顺序

1. **盘点与保护**：核对工作区和未提交改动，按授权范围查页面、导航、路由、首页与认证跳转；沿 [资产登记](../../../design/README.md#资产登记)、[组件清单](../components/component-inventory.md) 与 [Token 政策](../../../design/tokens.md) 查实际 Pen 导入/实例、CSS 变量消费者、预览和当前文档引用。区分模板示例与使用方真实业务，在当前回复或已有 change 中列明清理对象、保留项和待确认项，不另建长期清单；涉及 Pen 操作时先确认实际工具可用。不根据文件名或目录整批删除，不覆盖无关改动。
2. **确定目标**：沿用用户已给定的新方向与保留项；方向不明确时先澄清或按授权提出方案，不擅自把“清理”解释为重新设计。已要求重建但新方向尚未确定时，只能清理明确授权且确认无依赖的模板示例/失效预览，保留可运行样式和仍被引用的库；在资产登记注明旧视觉待替换，不把旧稿当新业务的目标基线，也不宣称重建完成。仅清理示例且保留风格时不改变当前基线的有效性。
3. **先替换再清理**：重建以 [global.css](../../../../frontend/src/shared/styles/global.css) 为正式值源，在授权范围内更新所需 Token 和受影响的组件样式，再通过全局 `pencil-design` 同步公共库及实际消费者。优先保留稳定的语义名、组件 API 和交互契约；确需更名时同步全部直接引用，不为兼容旧外观保留平行色板或组件。Pen 的读写、保存回读、主题表达与必要视觉确认遵循 [设计交付约定](../../../design/design-handoff.md)，不另建一套制稿流程。
4. **检查后移除**：确认保留内容不依赖删除对象、必要替代内容有效后，按授权移除模板展示页面及专属路由、导航、示例资源，或被替代的旧设计、预览和样式；同步直接引用，不只隐藏菜单而留下模板页面可直达。保留通用布局、响应式、可访问性及组件交互规则，不把所有设计/工程规范一起清空；保留真实业务、账号/权限、必要路由与 Router 基础、Provider、数据、密钥和 `.git`，不清空 Manager/OpenSpec/repair 或历史证据。同步受影响的资产登记、组件定位、视觉规范、Token 政策及直接引用，移除旧路径和失效 Frame ID，不重写历史记录。
5. **验证与交接**：按 [验证范围](../../common/README.md#验证范围) 和受影响端的实际命令检查，不擅自启动或发布服务。对修改对象分别记录结构、代码、运行与视觉的 `passed | failed | not_run`，核对支持主题下的有效值、焦点/禁用/错误等必要状态；CSS 引用或截图存在不代表渲染通过。缺工具、关键输入或有效验证时停止依赖步骤，保留可恢复源及未完成项，不把文档更新当成体系替换成功。

### 完成边界

产品化清理须核对默认首页、Logo 返回、登录后默认跳转与有效业务回跳、旧展示 URL、桌面和移动端导航以及相关文档引用。旧展示 URL 应进入 404 或明确的业务重定向，不再渲染模板展厅；认证、主题切换及公共组件仍可供业务使用。结构与静态检查不能代替浏览器验证，未执行的运行或视觉检查标记 `not_run`，不宣称产品体验已验收。

公共库提供当前项目需要的基础能力，不为目录齐全扩建组件。已有 `business.pen` 先按实际依赖保留或清理；没有真实业务设计需求时不新建空业务稿，后续需要时建立一个业务消费稿并登记，不为每次需求增加 Pen 文件。

初始化结果只记录在当前回复或已有 PR/change；重复调用时回读实际资产；未明确要求再次更换时只补未完成部分，不重置已建立的项目风格。需要的新视觉确认沿用已有设计流程，不增加独立 MD 审批或逐组件签字；没有业务需求时不编造 PRD 或业务代表页。

初始化结束后返回原协调者，后续业务仍由 `ui-ux-delivery` 读取当前项目规范并交付设计，再进入技术方案与实现。初始化接受只覆盖实际公共基线，不代替业务代表页确认或最终产品验收；仅请求初始化不自动开始整套业务开发。

## 上游代码同步

仅在明确要求集成或同步上游前端时执行以下内容；视觉初始化不触发来源代码覆盖。

从标准 frontend 整体复制代码和工程文件，再应用本项目 API/proxy、Docker 与文档导航差异；不手写“看起来相似”的组件版本。固定来源提交、保留来源 lockfile，校验文件哈希；记录集成例外和原因。

同步清单见 [frontend-source.json](../../../../scripts/frontend-source.json)。`python3 scripts/check_sources.py --frontend` 比较当前文件与同步收尾快照，列出未经记录的差异；清单是来源证据，不要求将后续业务代码回滚成模板。更新基线时重新审查例外，不能先删断言再宣称一致。

排除来源自身 docs、前端级 .codex/.claude、独立部署 Caddy/Railway、无关业务 HTML；不复制参考仓库其他目录。当前项目文档在 `docs/engineering/frontend` 按最终代码维护，frontend AGENTS 只导航。

安装、检查、开发与整栈启动见 [frontend README](../../../../frontend/README.md)。生产 API 不可用时不回退 mock；新能力先确认真实 backend 契约。公共 token、Theme、Provider、Router、组件只保留一份，不并行创建来源版和全栈版。
