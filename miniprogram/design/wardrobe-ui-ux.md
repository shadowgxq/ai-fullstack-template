# 智能衣柜设计交付

## 范围与来源

需求来源为 [当前 PRD](../../docs/product/01-prd-draft.md)，目标为微信小程序。当前设计包含登录资料、衣柜、偏好、推荐、穿着记录与统计的业务页面及必要局部。白底、深蓝文字、青绿色主色和整体样式方向已确认；最终页面与小程序宿主交互待用户验收。

设计源文件为 [wardrobe.pen](wardrobe.pen)，通过别名 `z` 导入 [公共库](../../frontend/design/core.lib.pen)。业务组合在消费稿内维护，公共库未修改。实现目标为仓库现有 `miniprogram/` 工程，采用 Taro + React + TypeScript；`frontend/` 保留 Web 模板。当前小程序已接入微信会话与衣柜列表、详情、添加编辑及私有媒体接口，其他业务页面仍由对应功能接入；最终宿主体验待运行验收。

## 样式与宿主

布局、字号、触控、底部操作和安全区规则唯一维护在 [业务移动 UI](wardrobe-ui-spec.md#布局与宿主)，通用移动规则见 [移动 UI](ui-spec.md)，颜色与主题来源见 [移动 Token](tokens.md)。主画布为 390 × 820 逻辑 px，左右留边 16px；Light/Dark 共用结构，不另做 PC 页面。

导航标题为 20px，主页面左侧提供个人入口，子页面提供返回，右侧预留微信系统胶囊。状态栏 44px、胶囊 88 × 32px、底部安全区 24px 均为设备展示尺寸，不能写成运行时常量；系统层不由业务重绘。微信宿主信息通过 [官方 API 定义](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts) 中的窗口和胶囊信息能力取得；当前业务宿主按实际测量安排导航、滚动与固定底部区，并订阅键盘高度，设备表现仍待验证。

每个页面视口引用唯一完整内容源，中间滚动与固定操作区分开；长内容保留在完整源中，不以缩小字号或删字段适配首屏。穿搭主操作高 50px，添加衣物主操作 52px，表单控件 48px、圆角 12px，为业务覆盖。三 Tab 为衣柜、穿搭、记录；统计归记录，个人是二级页。

## 交互及状态

### 添加与编辑衣物

基础字段按照片、名称、分类、主要颜色排列；更多属性默认收起，包含季节、场合、标签与备注，收起不清空内容。未填写时不默认选中季节、颜色或场合；展开示例中的春秋等为已填数据。

拍照和相册分别触发对应媒体来源；衣物只保存一张主照片，已选后支持移除、重新拍照或从相册更换。取消选择不改变原照片；失败保留名称及其他输入，不暗示自动识别。

照片或名称至少一项，规则见 [PRD §3.2](../../docs/product/01-prd-draft.md#32-衣物录入与管理)。点击添加时若两者均缺失，在照片/名称附近显示“请添加照片或填写衣物名称”，保留其他字段并引导补充；上传未成功不能视作已有有效照片。提交 pending 防重，失败保留输入并可重试，成功回衣柜显示新衣物。通用错误/加载表达复用 [移动状态规则](ui-spec.md#组件交互与状态) 及小程序端 Notice、StatePanel，不逐状态复制整页。

分类触发器打开 `phKmP`，选择后回填并关闭；清除分类回未知，关闭不选择保持原值。颜色为单选，快捷色块和 `zXmjy` 使用同一当前值，选中有勾选和名称，支持清除。季节、场合及标签为多选，再次点击取消；自定义标签弹层仅更新待保存表单，空白文本不能添加，重复标签不重复加入。图中选项为示例，不把列表数量当成已确认枚举。

底部“添加到衣柜”独立于滚动区域，滚动区可到达最后一个字段及说明；底部安全区不占按钮命中区域。键盘出现时收起固定操作区，焦点字段保持可见，收键盘后恢复。静态设计仅表达分区，真实键盘/滚动行为待端上验证。

编辑复用同一表单，带入已保存值，标题为“编辑衣物”，动作“保存修改”，更新当前对象；同样满足照片或名称至少一项。新衣物默认可穿，状态在详情管理，不要求首次逐项填写档案。

### 微信登录与个人

登录页仅提供“微信登录”，无密码、注册表单或强制手机号。点击后显示登录中；成功进入对应微信身份的衣柜，失败可重试，返回不展示个人数据。登录身份与头像昵称分开处理；不绘制旧式“授权获取头像昵称”弹窗。登录凭证能力依据 [微信官方 API 定义](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts)，资料填写能力依据 [官方头像昵称组件说明](https://github.com/wechat-miniprogram/mp-user-avatar)；设计未证明服务端会话已接入。

个人页 `QL83M / JGka6` 展示渐变资料头部与“衣物 / 穿着记录”内容 Tab，设置不再直接铺在个人页。当前主稿 `QL83M` 为衣物 Tab 的有数据状态，展示 4 件示例衣物的双列照片卡片、名称和类别/颜色，卡片素材与结构从 `zkPuC` 复制复用，卡片点击进入 `WV7wn`。资料头部明确区分编辑资料与账户设置。分类 Tab 右侧保留高 48px 的“＋ 添加”进入 `Ro2vL`，操作与当前内容同组，不另设重复的“我的衣物”标题与工具栏；记录 Tab 对应“＋ 记录”进入 `tz4GK`，属于同结构文案/目标差异，当前画布仍为衣物 Tab 静态状态。衣物预览下方“管理衣柜”进入已有 `ddC69`，分类、状态调整与完整管理只由衣柜页承接，不在个人页另造管理流程；空衣柜沿用 `JGka6` 内的局部引导 `XdK5f`，保留添加第一件衣物的入口。`H9XUdW` 是未登录引导，不是已登录个人页的空库存状态：标题为“我的”，展示登录插画、功能说明、微信登录按钮和资料选填提示，不展示资料头部、内容 Tab 或底部主导航。已登录个人页空库存通过 `q5sgBH` 展示资料头部、零数量 Tab 与空态组合，与未登录引导区分；内容引用 `JGka6`，空态引用 `SKORD`，只覆盖数量、可见性与适配尺寸，不维护独立内容副本。记录 Tab 无数据时复用同一空态结构，标题“还没有穿着记录”，动作“记录一次穿着”进入 `tz4GK`。有数据时分别复用 `zkPuC` 的衣物列表和 `C0p2tC` 的实际穿着记录结构，不新增收藏、发布或社交数据。切换只改变展示分类，不写入业务数据。

默认显示占位头像和“衣柜用户”，点击头像或昵称进入独立编辑页 `LgGyr`；该页沿用当前小程序导航、主题色与控件规范，以顶部头像编辑、基本信息分组和底部保存操作组织内容，仅提供头像及昵称，不引入参考图中的手机号、UID、性别或生日。头像及昵称选填，使用真实平台资料填写能力，不把资料授权作为登录前提。保存失败保留本次输入，返回不保存时保留原资料。齿轮进入独立设置页 `fkIRs`，唯一内容源为 `XzsEz`，承接个人资料、偏好、城市及退出；设置操作与个人页的内容展示分开。

偏好和城市分别进入已有页面/弹层，不设置整页“保存设置”。日期统一按北京时间计算，设置页不提供时区选择。退出使用共用确认结构，文案明确仅退出当前登录、不删除衣物和历史；确认退出后清除当前登录状态及个人数据展示。

### 穿搭偏好

长期偏好页 `OgxoN / Z8EEvN` 包含“喜欢的风格 / 颜色”“避免的风格 / 颜色”“喜欢的场合”“避免的场合”和选填舒适度。“喜欢的场合”位于 `UIbzM`，“避免的场合”位于 `ViP2f`，后者在喜欢场合与舒适度之间，复用同一组多选 Chip 的结构和场合选项。两组均可留空或清除；同一场合同时选为喜欢与避免时，字段附近说明冲突并保留草稿，不悄悄删掉任一选择。保存成功后下次进入回显真实值；失败时保留所有已选项。

舒适度区标注“舒适度偏好（选填）”，示例为“例如怕冷或偏好宽松”，并说明“舒适度描述供 AI 参考，不保证满足；风格、颜色和场合的避免项会严格排除。”不以未记录的鞋跟、版型等属性暗示已保证文本禁忌。

当前源稿 SHA256 为 `98404673fa82e8955f6b07916eb91fa079feed9f27361054c8599450644f8494`。偏好在390px Light和360px Dark下完整内容高841px，视口滚动区644px，固定保存区和安全区独立；两主题与完整内容源已实际渲染查看，说明文字可读且无裁切。其他页面保持原生语义、公共库未变。该设计检查不代表客户端滚动、字体严格绑定或最终产品验收通过。

### 衣柜空页面

通用空态 `SKORD` 原先仅有局部示例，无法表达空库存时筛选区、固定添加区与底部导航的取舍，因此补充完整衣柜空页面 `w2ZdGv`（原衣柜内容源下方）；正文 `nslPK` 通过实例 `u3CdBx` 引用 `SKORD`，不为不同文案逐一复制页面。

当前新增节点已在编辑器回读；390px Light、360px Dark 和筛选空态长文案已查看实际渲染，结构与视觉检查 passed，375/430px 仅检查布局边界。磁盘回读尚未包含新增节点，需在编辑器保存 `wardrobe.pen` 后再次回读，暂不作为已持久化实现基线；未新增预览图片，未执行小程序运行检查或取得人工验收。

- 全部库存为空：隐藏数量及无意义的状态/类别筛选，保留顶部账户入口、微信宿主示意和底部三 Tab；正文显示“衣柜还是空的”，仅保留空态中的“添加衣物”，进入已有添加页 `Ro2vL`，不再叠加固定添加按钮。请求成功且全部库存为零才显示，不用于加载或网络错误。
- 库存存在但筛选无结果：保留数量、已选筛选和固定添加区，只将列表替换为同一 `SKORD`；标题“没有符合条件的衣物”，说明“试试其他条件，或清除筛选查看衣物。”，按钮“清除筛选”，清除当前筛选后重新展示列表。此为同结构内容/操作覆盖，不额外复制整页。
- 无记录、无推荐候选等其他空态仍沿用下文既有映射，本次不新增它们的完整页面。

### 穿着记录空页面

空态使用共用结构 `SKORD`，分别由衣柜 `w2ZdGv`、穿搭 `EI1eW`、记录 `Ozfkk` 与未登录引导 `H9XUdW` 覆盖插画、文案和动作。当前修订按用户四屏参考图调整；此前的主题及宽度检查不覆盖本次修订。当前仅核验 390px Light 编辑器渲染；其他宽度、Dark、磁盘保存回读与运行检查尚未验证。四类空态插画已替换为用户提供的 `bb379fa5-ef35-4b92-90a1-659682a01a2f.png` 素材图裁片，位于 `images/empty-state/{wardrobe,outfit,records,login}.png`；不再使用先前近似生成插画。文字、按钮和导航保留可编辑结构。

原通用空态未表达记录页概览、统计入口、固定补录区及底部导航的组合关系，因此补一张无历史记录的完整页面；保留近 30 天计数与衣柜统计入口，将列表替换为 `SKORD` 实例，不显示示例日期或衣物，不再叠加底部补录按钮。标题“还没有穿着记录”，说明“记录实际穿过的搭配，慢慢积累你的穿着日历。”，按钮“记录一次穿着”进入既有 `tz4GK`。无历史不能解读为从未穿过，统计入口仍可查看库存；加载或请求失败不使用零记录空态。

### 其他业务路径

- 衣柜及详情支持可穿、暂不可穿、已归档。归档复用确认结构，使用普通主操作，文案明确不参与推荐且保留历史；恢复沿用状态选择。没有永久删除衣物入口。
- 首页 `VAtRc` 默认展示完整推荐依据，天气、偏好、历史缺失如实说明，不设置展开/收起。场景只影响当前推荐；换一套重新推荐整组，替换单品仅更换所选库存，不写入历史。定位授权由微信宿主处理，拒绝或失败保留手动选城，不阻塞衣柜及推荐。
- 推荐生成中沿用穿搭页 `P9tls` 的底部操作区：次操作由“换一套”切换为“取消生成”，主操作“记录今天穿着”禁用；推荐内容区域用现有加载/状态组件说明当前请求。点击取消后，次操作显示“取消中”并防重复提交；收到 `cancelled` 后停止展示该次建议，给出重新生成入口。若生成先于取消完成，展示实际已生成的建议和原操作，不提示取消成功；取消失败时提示真实错误并允许对同一请求重试。离开页面只暂停轮询，不等于主动取消，也不产生穿着记录。该过程复用既有按钮、Notice 与状态区域，不增加独立页面或改变正常结果稿的结构。
- 推荐确认、补录及修正共用记录表单：分别带入推荐、自选衣物和原记录；保存前须确认实际日期和衣物。未来日期拒绝，同次提交防重，失败保留输入。修正动作“保存修改”。
- 实际穿着多选 `mKPcR` 点击“完成选择”才更新待保存表单，取消保持原值；它与 `AvD3c` 单品即时替换的行为不同。两者均不在确认记录前写入历史。
- 单品替换沿用 `AvD3c` 和穿搭页现有推荐说明区域，不新增页面。选择后保留其他衣物并显示校验中，暂时隐藏旧组合理由、禁用当前推荐的确认穿着操作；成功后同步展示组合与更新后的理由、缺失说明。失败保留选择草稿，复用 Notice 和按钮状态提供重试或重新选择；连续选择仅展示最后一次有效响应。数据契约见[推荐方案](../../docs/architecture/wardrobe/features/outfit-recommendation.md#6-单品替换取消和穿着确认)。
- 历史菜单引用公共 DropdownMenu `z:AwJuH` 的普通项/危险项结构，业务动作“修改记录、删除记录”；删除复用 `m0rZ7`，仅删除该记录与计数，不删衣物。
- 空衣柜、筛选为空、无记录、无推荐候选共用 `SKORD`，按原因分别提供添加衣物、清除筛选、补录、管理衣柜或调整偏好。无历史不写“从未穿过”；统计仍可展示库存，空趋势显示暂无已记录穿着。

## 组件与实现边界

消费稿继续使用真实库实例：Button `z:j8DiT/z:EthvI`、Input `z:mTBzU`、Label `z:QS5ir`、Select `z:MCyOS`、Textarea `z:v1JdnQ`、Dialog `z:ocBvt`。分类列表、颜色选择、Chip 多选及个人资料为业务组合，不提升公共库，不宣称公共 Select 已具备多选能力。

颜色、字号、行高主要绑定 `$z:*`；图片圆角/边界及 `wardrobe-mobile-*` 是消费稿内的业务几何。当前解析值及用途见 UI 规范。width/height 上未能持续保留的自定义变量引用以已解析值落图，变化后需重新解析；不把变量名当成已有 CSS/rpx 接线。

实现使用 `miniprogram/` 的 Taro 组件和 [本端组件清单](../../docs/engineering/miniprogram/components/component-inventory.md)，沿用 [开发规范](../../docs/engineering/miniprogram/standards/development.md) 的页面注册、请求、会话、生命周期与样式边界。现有 PageShell、Button、Field、Notice、StatePanel 可按真实 API 复用；公共库的 React export/props 仅证明 Web 能力，不作为小程序 import。

登录页已使用微信临时 code 交换 Backend 会话，消费默认 profile，并按账户与会话代次隔离请求、缓存及退出。衣物的拍照、相册入口分别指定来源，照片消费 Backend 私有媒体上传与认证下载，退出取消传输并丢弃临时路径；真实微信配置、媒体权限和宿主操作仍待接入验证。定位、头像昵称填写及其他业务 API 由对应功能接通。

模板保留原生导航和示例 Tab 作为辅助入口；登录及衣柜业务页采用按宿主状态栏与胶囊测量的自定义导航。当前登录后进入真实衣柜，列表、详情、表单使用独立滚动区、固定操作与业务弹层；穿搭、记录入口由对应业务实现时接通。模板的 375px 基准不改变本稿 390px 的比较条件；触控命中区按本端至少 48px，图标和按钮视觉可沿用画布尺寸，窄屏采用流式布局而非整体缩放。具体业务覆盖见 [业务移动 UI](wardrobe-ui-spec.md)。图层、Reusable Frame 与公共组件数量不决定代码拆分。
